# Агрегаты

Описание ключевых агрегатов: границы, инварианты, ключ.

## Patient (Medical)
- **Ключ:** `patient_id` (UUID).
- **Границы:** демографические/контактные данные пациента, ссылки на медкарты
  (сами медданные — отдельные агрегаты, не покидают домен).
- **Инварианты:** пациент уникален; нельзя создать платёж/исследование для несуществующего пациента.

## AiStudy (AI)
- **Ключ:** `study_id`.
- **Границы:** запрос на исследование, входные метаданные, статус, результат инференса.
- **Инварианты:** исследование привязано к существующему `patient_id`; результат публикуется
  только при статусе `completed`; идемпотентность по `study_id`.

## LoanContract (Finance)
- **Ключ:** `loan_id`.
- **Границы:** условия кредита, сумма, ставка, график, статус.
- **Инварианты:** сумма > 0; договор привязан к клиенту; смена статуса только по допустимым переходам
  (`draft → active → closed`); строгая согласованность внутри домена.

## Payment (Finance)
- **Ключ:** `payment_id`.
- **Границы:** сумма, валюта, счёт-источник/получатель, статус.
- **Инварианты:** атомарность списания/зачисления (saga/транзакция в домене); идемпотентность по `payment_id`;
  баланс счёта не уходит ниже допустимого.

## FinancialReport (Operations)
- **Ключ:** `report_id` (период + домен).
- **Границы:** агрегированные финпоказатели за период.
- **Инварианты:** отчёт строится только из подтверждённых событий; пересборка идемпотентна по периоду.

> Между агрегатами разных доменов — только eventual consistency через события.
> Внутри финансового домена операции, требующие строгой согласованности, выполняются транзакционно.

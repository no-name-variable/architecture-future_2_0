# Event Storming — целевая событийная архитектура

Легенда: 🟧 событие (факт) · 🟦 команда · 🟨 агрегат · 🟩 политика/реакция · 🟪 read-model.

```mermaid
flowchart LR
  %% Medical
  C1[🟦 Зарегистрировать пациента] --> E1[🟧 Зарегистрирован новый пациент]
  E1 --> AGR1[🟨 Patient]
  E1 --> P1[🟩 Запросить ИИ-исследование]

  %% AI
  P1 --> C2[🟦 Запустить ИИ-исследование]
  C2 --> E2[🟧 Пройдено исследование ИИ]
  E2 --> AGR2[🟨 AiStudy]
  E2 --> RM1[🟪 Витрина: загрузка клиник]

  %% Fintech
  C3[🟦 Оформить кредит] --> E3[🟧 Создан кредитный договор]
  E3 --> AGR3[🟨 LoanContract]
  C4[🟦 Провести платёж] --> E4[🟧 Проведён платёж]
  E4 --> AGR4[🟨 Payment]
  E3 --> P2[🟩 Обновить финотчётность]
  E4 --> P2

  %% Operations
  P2 --> E5[🟧 Сформирована финотчётность]
  E5 --> AGR5[🟨 FinancialReport]

  %% Analytics
  E1 -. без медданных .-> RM2[🟪 Self-service BI витрины]
  E3 --> RM2
  E4 --> RM2
  E2 --> RM2
  E5 --> RM2
```

## Источники и подписчики событий

| Событие | Источник (домен) | Подписчики |
|---|---|---|
| Зарегистрирован новый пациент | Medical | AI, Analytics |
| Пройдено исследование ИИ | AI | Medical, Analytics |
| Создан кредитный договор | Finance | Operations (финотчётность), Analytics |
| Проведён платёж | Finance | Operations, Analytics |
| Сформирована финотчётность | Operations | Analytics |

Все события проходят через Kafka со Schema Registry; необработанные сообщения уходят в DLQ.

# Обоснование конфигурации Terraform

Учебный стенд состоит из изолированной VPC-сети, подсети, загрузочного SSD-диска и
виртуальной машины. Все четыре ресурса создаются Terraform и связаны ссылками на
атрибуты, поэтому порядок развёртывания вычисляется автоматически. Вручную заранее
создаются только Yandex Cloud, каталог, IAM-доступ и публичный SSH-ключ.

Для стенда выбрана ВМ `standard-v3` с 2 vCPU и 4 ГБ RAM: этого достаточно для
небольшого приложения или агента сбора данных, а параметры можно увеличить без
изменения кода. SSD на 30 ГБ ускоряет запуск и работу сервисов. NAT включён для
учебного подключения и загрузки пакетов; в production доступ следует ограничить
через bastion/VPN, security groups и приватные endpoints.

Декларативный подход хранит желаемое состояние рядом с проектом. `terraform plan`
показывает изменение до применения, а один и тот же код воспроизводит среду после
сбоя или создаёт новое окружение с другими значениями переменных. Это снижает число
ручных ошибок, упрощает ревью и позволяет масштабировать инфраструктуру через
модули, циклы и CI/CD.

## Проверка

```bash
cd Task4
export YC_TOKEN="..."
terraform init
terraform fmt -check
terraform validate
terraform plan -out=tfplan
terraform apply tfplan
```

После запуска с реальными `cloud_id`, `folder_id`, `image_id`, SSH-ключом и
`YC_TOKEN` скриншот успешного `terraform apply` сохраняется как `apply-result.png`.
